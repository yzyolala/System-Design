## 相关公开反馈真题

### Amazon：设计短链接服务 / Design a URL Shortener

**标签：公开反馈真题（2025）。** [来源：候选人反馈汇总](https://www.reddit.com/r/leetcode/comments/1lvnd0t/)

**与本节的对应关系（学习映射）：** 关联较弱：可讨论允许缓存的重定向响应和跳转统计取舍；普通短链接服务不应为了有 CDN 而硬加 CDN。

**设计参考答案（非公司标准答案）：**

我先明确创建短链接和访问跳转两个核心功能，确认链接能否修改、是否过期、读写比例与峰值。API 提供创建与按短码跳转，数据库保存 code、target_url、owner、expires_at。短码可由唯一 ID 编码，或随机生成并通过唯一约束处理冲突；自定义别名同样需要原子占用。

跳转服务无状态化，先查缓存，miss 回源，验证过期或禁用状态后返回适当重定向。允许修改或需要可控统计时，避免不加分析地使用永久缓存的重定向。点击事件异步记录；读热点用缓存与副本，容量达到上限时按短码分片。刚创建后立即读取、链接删除与缓存失效都要定义一致性；故障时限流回源，不能假设 DB 能承担全部访问。

本节未核实到可独立归属某公司的逐字追问题目；上面的完整题只是本节知识的应用入口。

## 优先练习的面试追问

以下均为本节练习题，英文用于口述训练，不是公开面经逐字引文。每题保留速记要点，并附可口述的参考答案；方案需结合面试官给定的规模和约束调整。

### Q1. 设计面向全球用户的图片分发服务。

**英文口述：** Design global image delivery.

**继续追问：** 图片内容、元数据和动态 API 分别走哪条路径？

**回答要点：** 对象存储保存图片，CDN 分发允许缓存的内容，API 管理元数据和权限。关注带宽、命中率、回源流量与热点。此题是本节练习，不是已确认公司真题。

**参考答案（可口述）：**

我先澄清公开或私有图片、尺寸、上传量、下载量和区域分布。客户端通过授权上传到对象存储，API 保存图片 ID、对象路径、所有者与状态，后台生成需要的尺寸；下载从 CDN 获取图片，元数据查询走应用 API。

CDN hit 直接返回，miss 从源站拉取并缓存。对象存储承担持久化，CDN 承担分发；我会选择合适的 cache key、TTL 与版本化路径，监控命中率、回源带宽和错误率。私有图片要在分发入口验证访问权限，不能简单开放源站。

### Q2. 头像更新了，用户仍看到旧图，如何解决？

**英文口述：** How would you invalidate stale CDN content?

**继续追问：** 版本化 URL 和主动刷新各有什么代价？

**回答要点：** 新内容使用新版本 URL，并更新引用；固定 URL 可主动刷新并配置 TTL。URL 查询参数是否区分缓存取决于 cache key 配置。

**参考答案（可口述）：**

首选让新头像有新对象路径，例如 avatar/user123/v2.jpg，并在用户资料中更新引用。旧头像可以保持原缓存，新的页面请求新 URL，就不会依赖全球立即清除旧对象。

如果业务必须使用固定 URL，则结合缓存刷新、重新验证与 TTL，但浏览器也可能有旧缓存，刷新 CDN 不等于清除所有客户端缓存。使用 ?v=2 时必须确认 CDN 的 cache key 确实包含参数；否则两个 URL 仍可能命中同一项。

### Q3. 热门图片爆火，多个边缘节点同时 miss，怎么办？

**英文口述：** How would you protect the origin during a traffic spike?

**继续追问：** CDN 故障后全部回源是否安全？

**回答要点：** 考虑分层缓存、回源请求合并、热点预热与源站限流。fallback 需受容量限制，必要时降级，不能无限回源。

**参考答案（可口述）：**

单个边缘节点可以合并同一对象的并发回源；多个边缘节点之间可通过上层缓存或 origin shield 减少源站请求。预先知道的热门内容可预热，但无限预热所有内容不划算。

源站仍需要并发上限和保护。CDN 故障时，fallback 要按备用通道容量限流，必要时返回占位内容或暂时失败，不能自动把全部流量砸向小源站。我会同时监控边缘命中、回源速率和源站饱和度，区分热度增长与缓存配置错误。

### Q4. 带用户权限的数据能放 CDN 吗？

**英文口述：** Can authenticated content be served through a CDN?

**继续追问：** 如何防止一个用户看到另一个用户的内容？

**回答要点：** 先区分内容分发和共享缓存。私有内容需授权与正确缓存策略；动态 API 也可以经过 CDN，但不代表能安全共享缓存。

**参考答案（可口述）：**

可以，但必须明确“经过 CDN”与“所有人共享缓存”不同。私有文件可使用短期签名 URL/cookie，在边缘验证授权，同时限制源站直接访问，防止绕过入口。

个性化 API 若不适合共享缓存，可以经过 CDN 但不缓存响应；如确需缓存，cache key 与授权规则必须确保响应不会被跨用户错误复用。签名到期与权限撤销也是取舍：短有效期缩小访问窗口，若要求立即撤销就需要额外验证机制。[CloudFront 官方参考](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/PrivateContent.html)。
