# 06. 无状态 Web 层：面试题与答案

## 面试真题

### Amazon：设计短链接服务 / Design a URL Shortener

**答案：**

我先明确创建短链接和访问跳转两个核心功能，确认链接能否修改、是否过期、读写比例与峰值。API 提供创建与按短码跳转，数据库保存 code、target_url、owner、expires_at。短码可由唯一 ID 编码，或随机生成并通过唯一约束处理冲突；自定义别名同样需要原子占用。

跳转服务无状态化，先查缓存，miss 回源，验证过期或禁用状态后返回适当重定向。允许修改或需要可控统计时，避免不加分析地使用永久缓存的重定向。点击事件异步记录；读热点用缓存与副本，容量达到上限时按短码分片。刚创建后立即读取、链接删除与缓存失效都要定义一致性；故障时限流回源，不能假设 DB 能承担全部访问。

例如写入成功后缓存尚未填充，首次跳转应从能看到该记录的数据库读取。禁用链接若要求立即生效，不能只依赖长 TTL 的缓存；还要协调版本或权威校验。创建接口和跳转接口可独立扩容，因为两者负载通常差异很大。

[题目来源](https://www.reddit.com/r/leetcode/comments/1lvnd0t/)

### Meta：设计 LeetCode / Design LeetCode

**答案：**

先确认题目浏览、提交判题、结果查询、比赛和排行榜的范围。API 保存 submission_id、用户、题目、代码引用、语言和状态，再可靠发布判题任务，返回 pending。worker 在隔离沙箱内编译运行，用 CPU、内存、时间和网络限制保护平台，测试数据也需受保护。

判题结果持久化后更新提交状态，同一 submission_id 的重复执行不能重复修改成绩。队列按语言或资源类型分组，扩容受沙箱启动和下游容量约束。比赛排名从可信结果与规则计算，缓存或增量更新读模型；监控等待时间、判题失败、热点比赛和重复消息。仅加入 MQ 不足以完成代码隔离与比赛正确性设计。

比赛题目、测试数据和用户代码要分别设权限。超时、编译错误、答案错误与平台内部失败是不同结果，平台故障可以重试，用户代码错误通常直接返回。重复任务的完成状态使用条件更新，避免晚到结果覆盖已经确认的成绩。

[题目来源](https://www.reddit.com/r/leetcode/comments/1lvnd0t/)

## 本节练习题

### Q1. 增加 Web Server 后，用户偶尔掉登录，为什么？

请求落到另一台机器会发生什么？

**答案：**

最常见原因是 session 只保存在原服务器的内存或磁盘。用户登录后下一次请求被分到新实例，新实例找不到 session，就将用户视为未登录。我会先检查是否存在这种实例相关性。

解决方案是让客户端携带 session ID，各实例通过同一高可用 session 存储查询，并共享有效的校验配置。上线时可暂时使用粘性路由完成迁移，或根据业务让旧会话逐步到期；同时确认密钥、Cookie 域名与过期配置一致，因为掉登录也可能来自配置问题。

验证时用同一个 session ID 连续访问不同实例，检查登录状态是否一致；再主动停止一个实例并重试。这样能区分本地会话问题和密钥、Cookie、过期时间等配置问题。

### Q2. 为什么不一直使用 sticky session？

缩容、实例故障和用户负载不均怎么办？

**答案：**

sticky session 把用户绑定到某个实例，适合短期减少改动，但该用户的负载不能自由分摊，新机器也未必马上接到足够流量。绑定实例故障或缩容时，本地会话可能丢失，粘性路由本身不能保存状态。

如果继续使用它，就要说明会话复制、故障恢复与连接排空。对于普通 HTTP 服务，我更倾向外置跨请求状态，让新实例直接服务任意用户；对于 WebSocket 等长连接，连接仍有实例归属，但持久状态和重连恢复可以外置。

缩容时先停止接受新连接，再给在途请求完成时间。WebSocket 的连接归属不会因状态外置而消失，需要客户端重连、恢复订阅和补拉遗漏消息。

### Q3. session、头像、临时上传文件分别放哪里？

状态外置是否等于全部放 Redis？

**答案：**

session 体积小、读取频繁并有有效期，可以放共享 key-value 存储，选择满足耐久与可用性要求的部署；关键业务状态则放数据库。头像二进制放对象存储，数据库记录对象地址、所有者和版本，CDN 分发允许缓存的内容。

临时上传可以使用带过期清理的对象路径，并持久化上传任务 ID 和状态。单实例临时文件适合可丢失、可重试的局部处理；如果后续请求或其他 worker 必须访问它，就不能把本地磁盘当作唯一来源。

worker 本地生成的缩略图在任务成功前应上传到共享存储，再持久化结果地址。若只把本地文件路径写入数据库，下一台实例接管时仍无法读取，系统其实没有完成状态外置。

### Q4. 共享 session 存储宕机怎么办？

是否允许旧 session？如何注销或撤销 token？

**答案：**

先配置跨故障域副本与切换，应用设短超时，防止所有线程都等待 session 存储。故障后是否接受请求取决于权限要求：不能可靠确认权限的敏感操作，应返回可重试错误或拒绝，而不是一律匿名放行。

自包含签名 token 可减少部分查询，但需要校验签名、有效期和目标服务。若权限撤销要立即生效，仍需额外服务端状态；只用离线 token 就要接受到过期前的撤销窗口。已有 session 可否读陈旧副本，也必须与注销语义一起定义。

例如支付或修改权限需要最新身份状态，可在存储不可用时拒绝；公开页面仍可返回。故障策略按操作分别定义，不能为了服务“看起来可用”而忽略权限验证。
