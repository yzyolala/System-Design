# 10. 数据库扩展与分片：面试题与答案

## Google：设计分布式缓存

**参考答案：**

1. 提供 get、set、delete 和 TTL；按 key 将请求路由到分片，节点在内存保存数据，容量不足时用 LRU/LFU 淘汰。
2. 路由可用一致性哈希或哈希槽；每片按需要设置副本，主节点故障时切换。异步复制可能丢最近写入，要明确业务容忍度。
3. 新增节点时分批迁移分片并更新路由；单个热点 key 用本地缓存或读副本分担，一致性哈希不能自动消除单 key 热点。
4. 缓存 miss 使用请求合并，故障时限流回源。监控命中率、内存、尾延迟与热点。

[题目来源](https://www.reddit.com/r/leetcode/comments/1lvnd0t/)

## Amazon：设计短链接服务

**参考答案：**

1. 提供创建短链接和跳转两个接口；数据库保存短码、原 URL、创建者和过期时间。
2. 短码使用唯一 ID 编码，或随机生成并用数据库唯一约束处理冲突。跳转时先查缓存，miss 查数据库，检查有效期后返回重定向。
3. Web 服务保持无状态，使用负载均衡扩容；热点链接放缓存，点击统计异步处理。数据库达到容量或写入上限后按短码分片。
4. 创建后立即访问要避免读副本延迟；修改或删除链接要失效缓存。缓存故障时限制回源，保护数据库。
